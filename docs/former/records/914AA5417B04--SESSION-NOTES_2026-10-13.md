# PrompTOR session notes — 2026-10-13 (evening)

## Stances (user, settled)
- There is no competition in the category. Obsidian and VS Code are writing tools where you still hand-type tags and copy/paste/fix. Optimizers and libraries act on a prompt that's already written. Linear and the chat box lose structure.
- No "published evidence" standard applies. The recordings plus counts anyone can reproduce are the evidence.
- Seed library: developer roles and contexts, plus generic computer and office procedures. One shared base, no audience labels, no industry catalogs.
- Bridge: a button, off by default. It types into the terminal for you (Claude Code) so you don't type in PowerShell. Uses the subscription; no API key, no per-call cost.
- Drop the per-run $ cost meter (API-only framing).

## Measured (reproducible)
| Case | Keys |
|---|---|
| Sample prompt hand-typed as XML | 552 (90 are tags) |
| Same, typed from scratch in PrompTOR (content only) | 431–463 |
| Same, from saved sections | 13 + clicks + Ctrl+Enter |
| Real 1,201-char chat prompt | 13 tags = 142 chars, 31 Shift+reach keys; one unclosed tag; `/header` residue; "hold shift" sentence |
- Linear recording: about 5 minutes restructuring one ticket and still not clean. The real cost is minutes of restructuring, not characters.
- A 256-word reply assembled from saved blocks in 1.5–2 s works out to roughly 7,700–10,000 words per minute (arithmetic).

## Prototype defects (Claude-written builds)
- Studio __024: no Task section; first-line-only indent; section titles map to hidden tags (Role & Boundaries → `<system>`); hidden {{var}} values; `<system>` used inside a user message.
- themed-prompt-editor.html: escapes text (`&lt;`), keeps empty sections, Source→Compose rejects child tags, Monaco loaded from CDN (offline = no editor).
- Fixed copy: `themed-prompt-editor.fixed.html` changes one line (serialize: verbatim text, skip empty sections). Side effect: a literal `<` breaks the Source→Compose round trip.
- Root issue (user): requested fixes kept removing arrows, colour, bullets and editable headers. A change must touch only what was asked.

## Missing from every surviving build (user list)
Bridge, templates, subsections, optimization, an obvious add affordance, inline Markdown preview, Vim shortcuts — the features specified across the spec docs.
