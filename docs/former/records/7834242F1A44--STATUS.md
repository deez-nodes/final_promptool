# PrompTOR status

## Independent editor — 2026-09-20, current Codex task

- The user explicitly requested a completely separate editor after concurrent edits were detected in `promptor.html`. This task did not apply its prepared patch to that app. The other writer's app and its files remain under that writer's control.
- New app: `promptor-editor.html`. Neutral slate/white surfaces, semantic section colours, an independent storage key (`promptor-editor-v1`), and no build/install requirement. This is not a replacement for `promptor.html`.
- Preview: `http://127.0.0.1:8942/`, served by `node serve-editor.cjs`. The server binds only to loopback and serves only the new editor. Open this URL consistently: file URLs and other ports have separate browser storage.
- XML is the default. Named sections and optional named/numbered points generate their own tags under `<prompt>`. Text containing `<`, `&`, or `]]>` uses lossless CDATA, so literal reference/code text cannot become structural markup. Markdown and plain-text export remain selectable.
- Implemented: independent section editing, reorder/fold/include/remove/Undo; Enter/list continuation; exact copy and Ctrl+Enter; saved prompts; individual-section pulling; cursor insertion into sections or points; explicit original-piece editing; filled starting points with points and folded defaults; optional Keep for next turn and saved previous turns; text-file document sections; a persistent source pane with exact selections, optional comments, source names/ranges, and no send action; safe formatted Markdown reading view; backup merge/import/export and read-only import from the earlier app when its storage is available on the same origin.
- Safety: unreadable saved state is not overwritten and can be downloaded; storage write failures are visible; failed imports roll back; imports preserve the active draft. Actual user storage was not cleared or populated with fixtures.
- Verification: `node verify-editor.cjs` passed against both the file and the served app (the final expanded suite passed against the served app). Tests use isolated Edge contexts and cover XML parse/text round trips, generated points, lists, Undo, filled starts, three quotes/two comments, exact copied text, insertion into points, library-copy independence, reload/new-page persistence, save without duplicate prompts, text-file attachment, backup recovery, original-app storage preservation, next-turn carry, safe Markdown rendering, mobile overflow, and corrupt-state recovery. Desktop and mobile screenshots were inspected: `editor-open.png`, `editor-desktop.png`, `editor-mobile.png`, `editor-mobile-writing.png`.
- Limit: in-app browser opening was queued, but CUA failed twice before browser access (`apply deny-read ACLs`); persistence in the user's actual Codex browser is not certified. Rich formatting while typing is not implemented: Reading view renders Markdown and clicking it returns to plain-text editing. No direct model bridge, automatic response splitting, or task-management suite was added.
- Next action: use the running independent editor and verify a real draft survives reopening in the chosen host. The older PLAN.md and checkpoint list below describe the other app; this task has not marked that roadmap complete.

## Verification
`node verify.cjs` and `node verify-workflows.cjs` pass at every checkpoint (isolated Edge, Playwright from the Codex runtime path). `preview-workflow.png` inspected at cp2, cp3, cp4 and cp6. Preview panes render local files as `data:` snapshots (no sibling files, no localStorage), which is why saving failed there and why the split showed unstyled. Fixed by `serve.cjs` + `.claude/launch.json`: at `http://localhost:4173/` the pane shows the styled app and `Draft saved locally` with data in localStorage (checked 2026-09-20). The desktop shortcut opens the file in the default browser, where it also persists; the two are separate storage.

## Known gaps
- `promptor.js` is still dense one-statement-per-function code moved verbatim; it needs formatting (Prettier, with the user's OK to fetch it) so normal edits replace patch scripts.
- Live Markdown/tag highlighting is not built (isolated spike; likely CodeMirror + bundler).
- Reply quoting is manual selection only; auto-splitting is an open question.
- One conversation at a time (the reply draft). Multiple conversations undecided.
- Base sections are pulled through the Pull dialog, not listed one-click in the library.
- PLAN.md predates v1: its items 1–5 are largely covered by cp1–cp5; item 0 (real-host persistence) and item 6 (reading surface) remain.
