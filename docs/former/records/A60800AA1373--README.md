# PrompTOR

A local prompt workspace with two base templates, a searchable library, live preview, and an acceptance checklist. Distinct pane backgrounds and violet, blue, amber, and teal sections make the editor easier to scan.

## Run

Requires Node.js 22.12+ (Node 24 recommended).

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. On Windows, use `npm.cmd` if PowerShell blocks `npm.ps1`.

```sh
npm test
npm run build
npm run preview
```

`dist/` contains the production site. Serve it over HTTP; opening `index.html` directly as a file does not load the TypeScript app.

## Use

- Choose **General prompt** or **Coding task**, then add a title and fill only the sections you need.
- Optional guidance expands under **More context & guidance**. Template changes preserve additional fields.
- File references are paths only. No file contents are uploaded or read. An optional base directory applies to new relative references.
- Copy or export the assembled Markdown. **Checklist** presents one acceptance criterion per line; it does not run tests or call an AI.
- Edits autosave in this browser. **Settings → Export backup** saves all items and settings as JSON. Imports merge items by ID, retaining the newer version.
- On desktop, drag either divider. Focus a divider and use arrow keys (Shift for larger steps), Home/End for size limits, or Enter to collapse/restore. Double-click also toggles collapse. Settings can reset pane sizes.
- Below 1200px the library is a drawer; below 768px Editor and Preview become separate views.

## Existing data

The original `promptology.html` remains as a legacy reference and migration entry point. Its **Export PrompTOR backup** button exports the data stored by that original page. Open it using the same browser and original address where the old library was saved, export, then import the JSON in the new app's Settings.

If old and new pages share an origin, PrompTOR automatically reads `ts_pm_items` and `ts_pm_basedir`. Legacy storage keys are never deleted. Migrated records retain their original data and any unmatched fields. Project-specific old templates become General or Coding; user text is preserved.

Browser storage is scoped to the browser profile, hostname, and port. Changing any of these does not move the library automatically. Use JSON backups to move between them.

Invalid saved data is left intact on load. Before a new save replaces it, an exact recovery copy is stored under `promptor:recovery:<timestamp>:<id>`. If storage is blocked or full, the editor shows a warning and retains current edits in memory; export a backup before closing.

## Module map

| Module | Responsibility |
| --- | --- |
| `src/model.ts`, `templates.ts` | Shared types and the two template schemas |
| `src/compiler.ts` | Pure prompt generation and checklist parsing |
| `src/storage.ts`, `migration.ts` | Validation, persistence, legacy conversion |
| `src/state.ts` | State updates and subscriptions |
| `src/main.ts` | App shell, event wiring, save scheduling |
| `src/ui/` | Editor, library, preview, and reusable splitters |
| `src/styles/` | Theme tokens, responsive layout, components |
| `src/export.ts` | Clipboard and file downloads |
| `tests/core.test.ts` | Compiler, migration, import, and recovery tests |

No backend, account, external font request, or AI API key is required. The app never sends your prompts to a model.
